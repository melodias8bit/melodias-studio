01

What a run leaves behind

The reference conditions timbre, not content. The still and the track are new material generated from the vibe, and every run writes a folder you can ship, re-render or inspect later.

  • StillAn 8-bit cover, 1280x720, with its seed and prompt stored for replay.
  • TrackAn original instrumental, about three and a half minutes, mastered for upload.
  • VideoA 1080p cut with the waveform, particles and channel branding.
  • YouTube copyTitle, description and hashtags, ready to paste.

Still

llama.cpp turns the vibe into an English prompt with the pixel style pinned; stable-diffusion.cpp returns three candidates. The seed and steps travel with the image, so a patched retry can be replayed.

Track

An original instrumental, 210 seconds by default. audio.cpp samples the source for timbre only, writes its own intro and outro, and the master is faded and normalized to -15 LUFS.

Video

The chosen still with a slow zoom, the waveform, pixel particles and the channel branding. Remotion by default; VIDEO_RENDERER=ffmpeg is the explicit fast path.

YouTube copy

Title, two opening paragraphs and 6 to 8 hashtags, written while the LLM is already loaded for the prompt. Rebuild it offline with the static template or with --opencode.

note The run is not resumable and a failed stage aborts it. That is deliberate: each stage reports its own error, so you know which service to look at instead of guessing from a half-finished folder.

02

Eleven stages, one take

The order is not arbitrary. The image is the most fragile stage, so it runs first; the download and the audio work share one GPU window.

  1. 01 Image prompt llama.cpp rewrites the vibe as an English prompt.
  2. 02 Prepare image Reference images rotate in; the seed and steps are fixed.
  3. 03 Image pool stable-diffusion.cpp draws three 1280x720 candidates.
  4. 04 Download yt-dlp pulls the source you linked.
  5. 05 Reference ffmpeg keeps the 60 s with the most energy.
  6. 06 Upload The window travels to the GPU box over scp.
  7. 07 Audio drafts audio.cpp returns three 60 s takes.
  8. 08 Review The judge pick wins automatically; the TUI still allows an override.
  9. 09 Final take The chosen seed drives the full 210 s at 32 steps.
  10. 10 Master + save Fade, loudness, meta.json and the history row.
  11. 11 Video Remotion renders 1080p with overlays and branding.

loop Before the review, score-v1 checks both sides and the retry loop regenerates only the side that missed, with a fixed patch table. A patch code is never applied twice and the pool stops growing at nine candidates per side.

03

Scored, not guessed

A run is not accepted because it looks fine. The deterministic rubric measures both sides, the judge adds the editorial read, and the numbers decide whether the loop runs at all.

Technical rubric

  • Image palette, contrast at 168 px, text, glow, saturation
  • Audio loudness, true peak, spectral centroid, energy above 5 kHz
  • Audio intro build, silence gaps, track length

Written to work/score.json and refreshable offline with melodias score. The text check uses tesseract; without it that metric is skipped and the rest is renormalized.

Editorial read

One multimodal call to gemini-4-argon through OpenCode Go sees 768 px JPEGs, hears 15 s MP3s and receives the deterministic findings. It returns a verdict and up to five must_fix codes.

No key means no call: the judge is skipped and the manual review still works. A failed judge is one log line, never an aborted run.

Acceptance

60% technical + 40% editorial
  • Total 80
  • Technical 85
  • Editorial 70

A run that misses after the loop is accepted_by_limit, not a failure. The history stores the outcome and the reason.

budget Up to two image rounds while stable-diffusion.cpp is up and one audio round when it lost eight points or more, independently of the image result.

06

Install

Generation happens on your own box. Bring the three HTTP services, point the config at them, and the pipeline does the rest.

Requirements

  • Rust 1.90+
  • yt-dlp
  • ffmpeg + ffprobe
  • llama.cpp
  • stable-diffusion.cpp
  • audio.cpp
  • Node 24+ + pnpm video only

The services can run on this machine or on another host over SSH. The defaults describe a single 24 GB P40, but nothing in the pipeline requires that card. Local mode is ssh_host = "" with the lifecycle commands empty.

The judge is optional and needs OPENCODE_API_KEY or OPENROUTER_API_KEY. Without a key the run pauses for a manual pick instead.

The installer verifies every prerequisite (Rust, yt-dlp, ffmpeg, ffprobe, ssh), clones the repository, builds the release binary and installs it into ~/.local/bin. Prefer the manual path? git clone the repository and run make install instead.

No arguments opens the TUI; the two arguments run the same pipeline headless and take the judge suggestion. Config starts from config.example.toml at $XDG_CONFIG_HOME/melodias-studio/config.toml.

07

After the run

A finished folder is not frozen. Rework one piece without paying for the whole pipeline, or read the results without touching a GPU.

CommandWhat it does
make image DIR=…Regenerate the thumbnail from the stored prompt, seed and references.
make judge DIR=…Review a finished run with the cloud judge; prints the verdict.
make score DIR=…Apply score-v1 offline and write work/score.json.
make youtube DIR=…Rebuild the upload copy from the template, or with --opencode.
make render DIR=…Re-render the video with Remotion, effects included.
make video DIR=…Cut the video with the ffmpeg fast path, no Remotion.
make historyQuery the local SQLite history, findings, costs and outcomes.
make dashboardServe the read-only charts on 127.0.0.1:7373.
make backfillScore older runs in output/ into the history database.
make refs ARGS=…Fetch, import or generate the optional reference library.
