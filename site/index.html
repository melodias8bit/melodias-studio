One vibe in. A song, a still, a video out.

melodias-studio is the release pipeline for 8-bit music channels. Drop in a reference URL and a vibe; it writes the prompt, draws the cover art, composes an original instrumental chiptune, cuts the 1080p video and hands you the YouTube copy. Eleven stages, one command, no editing timeline.

01

Two ways to run, same pipeline

Watch the eleven stages stream by in the TUI, or fire one headless command from CI and collect the folder. The headless run takes the judge pick automatically; the TUI lets you override any candidate.

No arguments opens the TUI; the two arguments run the same pipeline headless and take the judge suggestion. Config starts from config.example.toml at $XDG_CONFIG_HOME/melodias-studio/config.toml.

02

One run, everything included

A finished run is a folder you can ship, re-render or inspect later. The reference conditions timbre, not content: the still and the track are new material generated from the vibe.

Still

The vibe becomes an English prompt with the pixel style pinned. The seed and steps travel with the image, so a patched retry replays exactly.

Track

An original instrumental, 210 seconds by default. The source is sampled for timbre only, then the master is faded and normalized to -15 LUFS.

Video

The chosen still with a slow zoom, the waveform, pixel particles and channel branding. Remotion by default; the ffmpeg path is explicit and fast.

YouTube copy

Title, two opening paragraphs and hashtags, written while the language model is already loaded. Rebuild it offline or with the cloud pass.

note The run is not resumable and a failed stage aborts it. That is deliberate: each stage reports its own error, so you know which service to look at instead of guessing from a half-finished folder.

03

Eleven stages, one take

The order is not arbitrary. The image is the most fragile stage, so it runs first; the download and the audio work share one GPU window.

  1. 01Image promptllama.cpp rewrites the vibe as an English prompt.
  2. 02Prepare imageReference images rotate in; seed and steps are fixed.
  3. 03Image poolstable-diffusion.cpp draws three 1280x720 candidates.
  4. 04Downloadyt-dlp pulls the source you linked.
  5. 05Referenceffmpeg keeps the 60 s with the most energy.
  6. 06UploadThe window travels to the GPU box over scp.
  7. 07Audio draftsaudio.cpp returns three 60 s takes.
  8. 08ReviewThe judge pick wins automatically; the TUI still allows an override.
  9. 09Final takeThe chosen seed drives the full 210 s at 32 steps.
  10. 10Master + saveFade, loudness, meta.json and the history row.
  11. 11VideoRemotion renders 1080p with overlays and branding.

loop Before the review, the deterministic score checks both sides and the retry loop regenerates only the side that missed, with a fixed patch table. A patch code is never applied twice and the pool stops growing at nine candidates per side.

04

Scored, not guessed

A run is not accepted because it looks fine. The deterministic rubric measures both sides, the judge adds the editorial read, and the numbers decide whether the loop runs at all.

Technical rubric

  • Image palette, contrast at 168 px, text, glow, saturation
  • Audio loudness, true peak, spectral centroid, energy above 5 kHz
  • Audio intro build, silence gaps, track length

Written to work/score.json and refreshable offline with melodias score.

Editorial read

One multimodal call sees 768 px JPEGs, hears 15 s MP3s and receives the deterministic findings. It returns a verdict and up to five codes to fix.

No key means no call: the judge is skipped and the manual review still works. A failed judge is one log line, never an aborted run.

Acceptance

60% technical + 40% editorial
  • Total 80
  • Technical 85
  • Editorial 70

A run that misses after the loop is accepted_by_limit, not a failure. The history stores the outcome and the reason.

07

Install in one line

The installer verifies every prerequisite, builds the release binary and puts it on your PATH. No containers, no lock-in: it is a shell script you can read first.

Requirements

  • Rust 1.90+
  • yt-dlp
  • ffmpeg + ffprobe
  • llama.cpp
  • stable-diffusion.cpp
  • audio.cpp
  • Node 24+ + pnpm video only

The services can run on this machine or on another host over SSH. The defaults describe a single 24 GB card, but nothing in the pipeline requires that card. Local mode is ssh_host = "" with the lifecycle commands empty.

The judge is optional and needs OPENCODE_API_KEY or OPENROUTER_API_KEY. Without a key the run pauses for a manual pick in the TUI and takes the best-scored default headless.

Prefer the manual path? git clone the repository and run make install instead.

08

After the run

A finished folder is not frozen. Rework one piece without paying for the whole pipeline, or read the results without touching a GPU.

CommandWhat it does
make image DIR=…Regenerate the thumbnail from the stored prompt, seed and references.
make judge DIR=…Review a finished run with the cloud judge; prints the verdict.
make score DIR=…Apply the score offline and write work/score.json.
make youtube DIR=…Rebuild the upload copy from the template, or with --opencode.
make render DIR=…Re-render the video with Remotion, effects included.
make video DIR=…Cut the video with the ffmpeg fast path, no Remotion.
make historyQuery the local SQLite history, findings, costs and outcomes.
make export CSV=… OUT=…Render the dashboard overview as static files, no server needed.
make dashboardServe the read-only charts on 127.0.0.1:7373.
make backfillScore older runs in output/ into the history database.
make refs ARGS=…Fetch, import or generate the optional reference library.
09

Questions, answered

The short version. The repository is the long version.

Do I need a GPU?

Generation happens on your own box behind three HTTP services. The defaults describe a single 24 GB card, reached over SSH, but local mode works too. Scoring, judging replays, exports and the dashboard need no GPU at all.

Is the music original?

Yes. Every track is an original instrumental; the reference audio only conditions timbre. The run stores prompts and seeds, so any piece can be replayed or audited later.

What if I have no judge key?

Nothing breaks. The TUI pauses so you can pick the candidates yourself, and headless runs take the best-scored default. A failed judge call is one log line, never an aborted run.

Can I rework a finished run?

Yes, per piece: regenerate the still, re-run the judge or the score, rebuild the YouTube copy, or re-render the video, all from the stored folder. Nothing requires paying for the full pipeline twice.

What do the scores mean?

60 percent deterministic rubric plus 40 percent editorial read. The gates are 80 total, 85 technical and 70 editorial. A run that misses after the retry loop is recorded as accepted by limit, with the reason stored in history.

Where does my data live?

On your machine. Runs stay in output/, history in a local SQLite file, config in your home directory. The only network calls are the ones you configure: your GPU host and, optionally, the judge provider.
